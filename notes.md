# Заметки по ходу — AnimalGuide v18: интересные факты по расписанию

Черновик: план, решения по ходу, замеры.

## Условие

MCP-инструмент с периодическим выполнением: сохраняет данные (SQLite),
выполняется по расписанию, возвращает агрегированный результат. Итог —
агент, который работает 24/7 и периодически выдаёт сводку.

## Замысел

MCP-демон раз в **час** выбирает случайное животное из эталонного списка
MDD (Mammal Diversity Database, 6904 вида), собирает о нём выпуск
«интересных фактов» из Википедии, GBIF и MDD, сохраняет в SQLite. Раз в
сутки — сводка по накопленным выпускам. Выпуски и сводки доступны
инструментами MCP; в приложении — раздел «Интересные факты».

Термины (в v17 «подборка» и «карточка фактов» уже заняты):
- **выпуск** — набор фактов об одном виде, собранный по расписанию;
- **сводка** — агрегат по выпускам за период + короткий текст модели;
- пакет — `internal/trivia`, механизм — `trivia`.

## Решения, принятые до плана

1. Расписание живёт в отдельном долгоживущем процессе:
   `animals-mcp -http 127.0.0.1:8766` (Streamable HTTP). stdio-режим
   остаётся как в v17, без планировщика. «24/7» — это демон, а не вкладка.
2. Модель зовёт сам демон (свой `DEEPSEEK_API_KEY`). MCP sampling не
   годится: без подключённого клиента ночью ничего не соберётся.
3. Выбор вида — взвешенный, с порогом пригодности, иначе выпадают
   безымянные грызуны и летучие мыши без статьи и наблюдений.
4. Агрегат считает код (SQL), модель только пересказывает агрегат.

## План

### Этап 1. Слой MDD
- `internal/mdd`: загрузка `MDD.zip` с `raw.githubusercontent.com`
  (`If-None-Match` по `ETag`), пропуск `__MACOSX/` и `.DS_Store`, разбор
  `MDD_v*_species.csv`, `Diff_v*.csv`, `release.toml`.
- SQLite на `modernc.org/sqlite` (чистый Go, без cgo): `<data>/trivia.db`.
  Таблицы `mdd_release`, `mdd_species`, `mdd_changes`. Миграции версией схемы.
- Инструменты (`tools.Spec`, работают и в процессе, и через MCP):
  `mdd_get` (по id / латинскому / английскому названию), `mdd_search`
  (семейство, отряд, страна, статус МСОП), `mdd_changes` (изменения релиза).
- Тесты на урезанном архиве в `testdata/mdd/`.

### Этап 2. Выбор вида
- Кандидат из `mdd_species` → проверка пригодности: не domestic, есть статья
  в Википедии (ru, иначе en), в GBIF ≥ N наблюдений (по умолчанию 50).
- Веса: редкие статусы МСОП (CR/EN/VU) чаще; окно без повторов 30 дней.
- Отбракованные кандидаты — в журнал с причиной; не больше K попыток на запуск.
- Источник случайности подменяется в тестах.

### Этап 3. Сборка выпуска
- Без человека прогоняется конвейер карточки v17: идентификатор по
  латинскому названию из MDD, специалисты по разделам, трекер вызовов.
- Отдельный шаг «редактор» выбирает 3–5 интересных фактов; у каждого —
  ссылка на настоящий вызов (Википедия / GBIF / строка MDD). Страж
  отбрасывает факты без источника.
- Сверка кодом: наблюдения GBIF за последние 30 дней по странам против
  ареала MDD → отметка «наблюдён вне ареала».
- В БД: `issues` (вид, время, факты JSON, источники, токены, цена).

### Этап 4. Планировщик
- `internal/schedule`: период по умолчанию 1 час (`-every`, для
  демонстрации `1m`), подставные часы в тестах.
- Один запуск одновременно; `runs` — журнал (начало, конец, статус,
  ошибка, цена).
- После простоя догоняет не больше одного пропущенного запуска.
- Дневной лимит в деньгах (`-budget`, по умолчанию $0.50); исчерпан — пропуск
  с записью в журнал.
- Повтор при сетевой ошибке с отступом; раз в сутки проверка `ETag` MDD →
  при новом релизе перезагрузка и событие в сводке.

### Этап 5. Сводка
- Раз в сутки (время настраивается) и по запросу.
- Агрегат SQL: число выпусков, разбивка по отрядам / МСОП / биогеографическим
  областям, наблюдения GBIF за период, отметки «вне ареала», цена, сбои.
- Текст модели строится только из агрегата; в `summaries` хранятся оба.

### Этап 6. MCP-демон
- `animals-mcp -http :8766 -data <каталог>`: Streamable HTTP + планировщик.
- Новые инструменты: `facts_latest`, `facts_get` (по виду), `facts_search`,
  `summary_get` (период), `schedule_status`, `run_now`, плюс `mdd_*`.
- Сверка отпечатка описаний (`ErrDrift`) — как в v17.
- `mcp-list` умеет подключаться по URL.

### Этап 7. Приложение
- Механизм `trivia` («Интересные факты») в реестре `features`: выключатель,
  место в запросе, цена. Клиент к демону (`-trivia-server http://…`).
- Ведущий может взять готовый выпуск как источник — с пометкой даты сбора.
- Раздел «Интересные факты»: лента выпусков (факты со ссылками, отметки
  «вне ареала»), вкладка сводок, статус планировщика (следующий запуск,
  остаток бюджета), кнопка «Собрать сейчас». Обновление — опрос / SSE.
- Проверки интерфейса в headless Edge.

### Этап 8. Испытание И-8 и регрессия
- И-8 на ускоренных часах: N тиков → N выпусков, без повторов, у каждого
  факта источник; перезапуск демона → догон ≤ 1; сводка сходится с SQL;
  инструменты MCP отдают сохранённое; лимит бюджета останавливает сбор.
- Живой прогон с `-every 1m` ~10 минут; регрессия И-1…И-7.

### Этап 9. Документация
- README: запуск демона, работа 24/7 на Windows (Планировщик заданий или
  отдельная консоль), ключ, флаги. CHANGELOG `v18`. Тег `v18`.

## 2026-09-24

- Задание заведено, основа — код v17 одним коммитом, все тесты зелёные.
- Этап 1 (слой MDD) готов, три агента параллельно в своих worktree:
  загрузка/разбор (`parse.go`, `fetch.go`, `sync.go`), SQLite (`internal/db`
  с миграциями по компонентам, `mdd/sqlite.go`), инструменты + Memory +
  `mddtest.Conformance`. Контракт `mdd.go` зафиксирован заранее — слияние
  без конфликтов.
- SQLite прошла Conformance, написанный под Memory, с первого раза.
- Замеры: разбор настоящего архива 73 мс (6904 вида, 79 изменений);
  Replace 7000 видов ≈0,5 с; первая загрузка с сети 3,7 с, повтор по ETag
  (304) 0,34 с; база 8,3 МБ.
- По замечаниям агентов: «Domesticated» не страна (отбрасывается), IUCN
  «NT (as …)» → код, пустой Replace — ошибка в обеих реализациях, контракт
  уточнён (порядок и limit в Changes, правило Find при общих названиях).
- `animals-mcp`: `-data`, `-mdd-url`, `-mdd-sync`, `-mdd-update`; пустая
  база → загрузка в фоне. Клиент приложения считает отпечаток только по
  шести инструментам источников — mdd_* не дают ложного ErrDrift.
- Этап 2 (выбор вида) готов, снова три агента: WebChecker (статья через
  англовики + langlinks ru, GBIF match + occurrence count), Picker
  (статус ∝ вес × число видов, вид внутри — равновероятно, NoRepeat 30 дн,
  кэш проверок 30 дн), хранилище выборов (Memory, SQLite `trivia_pick`,
  `trivia_check`, `triviatest.PickStoreConformance`).
- Порядок проверок — GBIF, потом статья: на 152 случайных видах GBIF
  отказывает 35 % (26 % мало наблюдений, 9 % не знает названия), статьи нет
  у 0,7 %, и почти все они отсечены GBIF раньше. Пригодны ~64 % видов;
  медиана проверки ≈ 370 мс.
- Распределение статусов на 20 000 выборов — максимум отклонения 2,3σ.
- Живой сквозной прогон (8 выборов подряд, 6,2 с): лань, сумчатая мышь,
  Akodon surdus (VU), длиннонос Соссюра (EN), краснолобый лемур (VU), лев…
  Отказы — few_records и no_gbif, повторов нет.
- На будущее: кэш tools.Fetcher бессрочный — демону нужен свежий Fetcher
  на каждый выбор. no_gbif ловит и смену рода в MDD, которой ещё нет в GBIF
  (Megascapheus → Thomomys) — возможен запасной поиск по эпитету.
  PickStore понадобится Pick(ctx, id) для выпусков (этап 3).
- Этап 3 (сборка выпуска) готов, три агента: WebCollector (досье: MDD,
  статья ru/en — вступление + до 4 тематических разделов, GBIF-фасеты стран
  за всё время и за 30 дней, сверка ISO-2 → 241 имя стран MDD), LLMEditor +
  LLMVerifier (DeepSeek flash, JSON, повтор при мусоре, стабильный
  системный промпт ради кэша), хранилище выпусков (шаг 2 миграции

- Добавил: заголовок и вступление проверяются тем же запросом проверяющего;
