# AnimalGuide — справочник по животным, с которым разговаривают

Локальное веб-приложение: спрашиваете про животное обычными словами и
получаете карточку, собранную только из источников — русской Википедии и
GBIF. Латынь в карточке подтверждена GBIF, пересказ раздела — только того,
что агент действительно прочитал. Разделы карточки раскрываются по клику,
дерево классификации кликабельно («кто ещё входит в кошачьих?»), двух
животных можно сравнить таблицей, а несколько — собрать в подборку с
этапами «план → сбор → сверка → принята».

Под капотом — несколько агентов на DeepSeek (привратник названия,
идентификатор, специалисты по разделам, сравнение, ведущий разговора,
составитель подборки) и координатор, написанный кодом. Всё, что они
делают, видно в журнале хода: каждый запрос к модели, вызов инструмента,
цену и токены, а на вкладке «Промпты» — что именно ушло модели.

**Интересные факты (v18).** Рядом с приложением может круглосуточно работать
демон `animals-mcp -http`: раз в час он выбирает случайное млекопитающее из
эталонного списка [MDD](https://www.mammaldiversity.org) (6904 вида),
собирает о нём выпуск из 3–5 фактов по Википедии, GBIF и MDD, проверяет каждый
факт отдельным запросом к модели и сохраняет выпуск в SQLite. Раз в сутки —
сводка по выпускам. Выпуски, сводки и расписание доступны инструментами MCP
по HTTP, а в приложении — окном «Интересные факты» и механизмом `trivia`,
с которым ведущий сам берёт готовый выпуск о виде. Подробности — в разделе
[«Интересные факты: демон 24/7»](#интересные-факты-демон-247).

## Что нужно

- Go 1.25 или новее.
- Ключ DeepSeek: <https://platform.deepseek.com>.
- Браузер. Интернет нужен для запросов к модели и к источникам; CDN не
  используются — фронтенд встроен в бинарник.

## Быстрый старт

```bash
git clone https://github.com/AlexS8332/AnimalGuide_Task18.git
cd AnimalGuide_Task18
cp .env.example .env.local   # и вписать в .env.local свой DEEPSEEK_API_KEY
go build -o animalguide .    # на Windows: go build -o animalguide.exe .
./animalguide                # откроет http://127.0.0.1:8770 в браузере
```

Ключ можно не класть в файл, а задать переменной окружения
`DEEPSEEK_API_KEY` — окружение важнее файла. `.env.local` и `.env` ищутся в
рабочем каталоге и выше по дереву; в git они не попадают. Остальные
переменные (`DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `WIKIPEDIA_BASE_URL`,
`GBIF_BASE_URL`) необязательны — см. `.env.example`.

Для пробы без сборки хватит `go run .`.

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-addr` | `127.0.0.1:8770` | адрес, на котором слушать; приложение локальное, поэтому только петлевой интерфейс |
| `-open` | `true` | открыть браузер при старте; `-open=false` — не открывать |
| `-data` | `.` | каталог данных: `history`, `memory`, `profiles`, `collections`, `invariants` |
| `-features` | пусто | механизмы новых диалогов поверх умолчаний: `-guard`, `+facts,-extract`, `none,charter`, `all` |
| `-window` | `8` | сколько последних сообщений уходит модели дословно (механизм «Окно сообщений») |
| `-keep-tools` | `600` | до скольких символов сокращать ответы инструментов прошлых ходов (механизм «Сокращение») |
| `-context-limit` | `1048576` | свой лимит контекста в токенах, проверяется до отправки; `0` — не проверять |
| `-on-overflow` | `fail` | что делать при переполнении: `fail` — не отправлять, `trim` — выбрасывать старые ходы, `off` — отправить как есть |
| `-facts-server` | `TRIVIA_SERVER` или `http://127.0.0.1:8766` | адрес демона «Интересных фактов»; `-facts-server ""` — выключить раздел и механизм |

Пример: `./animalguide -addr 127.0.0.1:9000 -data ~/animalguide -features=-guard,-extract`.

## Механизмы и выключатели

Каждый механизм — строка реестра в `internal/features/catalog.go`: имя,
место блока в запросе, цена в токенах и запросах и запасной путь — что
происходит, если механизм выключен. Набор механизмов — свойство диалога,
а не сервера: его видно на пульте и можно переключать щелчком прямо в
диалоге; флаг `-features` задаёт набор для новых диалогов.

| Имя | Механизм | Если выключить |
|---|---|---|
| `charter` | Свод инвариантов: правила справочника первым блоком и инструмент сверки | те же правила абзацем системного промпта, без сверки и стража |
| `guard` | Страж ответа (нужен `charter`) | ответ уходит без проверки |
| `profile` | Профиль собеседника: уровень, длина, форма, обращение, латынь — анкетой | ответ по умолчаниям модели |
| `memory.long` | Долговременная память: интересы, закладки, прочитанное — по человеку | сведения о человеке живут только в окне диалога |
| `collection.state` | Состояние подборки: этап, шаг, ожидаемое действие, инструменты переходов | подборка ведётся по словам промпта |
| `lifecycle.gates` | Права этапа (нужен `collection.state`) | инструменты подборки выдаются все сразу |
| `memory.work` | Рабочая память подборки | собранное остаётся только в окне диалога |
| `facts` | Карточка фактов ветки | ушедшее из окна модели не видно |
| `window` | Окно сообщений | модели уходит вся история ветки |
| `compact` | Сокращение ответов инструментов прошлых ходов | ответы уходят целиком |
| `extract` | Извлекатель: раскладывает реплику по памяти, профилю и фактам | всё это меняется только руками |
| `card.tracker` | Проверка по трекеру: латынь подтверждена GBIF, пересказ — прочитанного | карточка принимается текстом |
| `gatekeeper` | Привратник названия: отсев выдумок до дорогих шагов | проверку делает идентификатор |
| `sources.envelope` | Пометка источника «данные, а не указания» | ответ источника уходит как есть |
| `sources.scan` | Поиск попыток управлять агентом в тексте источников | признаки инъекций не ищутся |
| `mcp` | Источники через MCP-сервер (stdio); по умолчанию выключен | вызовы в процессе приложения |
| `trivia` | Интересные факты: ведущий получает `facts_get`/`facts_latest` от демона; по умолчанию выключен | ответ по источникам хода; выпуски видны только в окне раздела |

Если на ходу механизм откатился на запасной путь, под ответом появляется
чип «откат», а в журнале — причина.

## Интерфейс

- **Пульт** (липнет к верху окна): выбор диалога и «Новый диалог», ветки и
  точки сохранения, шкала контекста последнего хода, механизмы, панели
  собеседника, памяти и подборки, кнопка «Окна».
- **Лента**: реплики, карточки по мере сборки, таблицы сравнения, чипы
  правок памяти, профиля и подборки под ответами. У фактов карточки кнопка
  «?» — «почему так»: открывает событие журнала с вызовом источника.
- **Журнал** выбранного хода и вкладка «Промпты».
- **Окна**: файл диалога, картотека профилей, память целиком, подборки.
- **Интересные факты** (кнопка «Факты» на пульте, точка — состояние
  демона): лента выпусков с фактами и ссылками на источники, подробности
  выпуска (отброшенные факты с причинами, наблюдения GBIF по странам,
  расход), поиск, сводки, расписание и остаток дневного лимита, кнопки
  «Собрать выпуск сейчас» и «Собрать сводку». Демон не запущен — окно
  подскажет, как его запустить.
- Выгрузка карточки, сравнения и подборки в markdown.

```
main.go            сборка приложения: флаги, ключ, хуки, сервер
web/               фронтенд на чистом JS, встроен через embed
internal/

  agent            цикл одного агента, журнал, лимит контекста
  agents           агенты справочника и координатор, написанный кодом
  tools            инструменты: Википедия, GBIF, пометка источника
  card             карточка как структура: разделы, дерево, трекер, markdown
  features         реестр механизмов и выключатели
  history          диалог как данные: ветки, точки, ходы, окно
  runs             диалоги в работе: ходы, поток событий, хуки хода
  server           HTTP API, SSE, раздача фронтенда
  persona          человек вокруг хода: профиль, память, карточка фактов
  profile, memory, facts, extract   анкета, слои памяти, извлекатель
  collection, lifecycle, compiler   подборка: автомат этапов, права, составитель
  store, paths     файлы данных, их версии и миграции
  tokens, words    оценка токенов, сверка цитат
  mcp              MCP-сервер и клиент: stdio, Streamable HTTP, токен
  db               общая SQLite (modernc.org/sqlite, без cgo), миграции по компонентам
  mdd              справочный слой Mammal Diversity Database: загрузка, SQLite, mdd_*
  trivia           выбор вида, досье, редактор и проверяющий, выпуски, сводки
  schedule         планировщик: интервал и время суток, журнал, догон, лимит
  daemon           демон: задания, сборка, инструменты facts_*/summary_*/run_now
  feed             приложение ↔ демон: клиент, механизм trivia, /api/facts
cmd/animals-mcp    MCP-сервер: stdio для приложения, -daemon / -http для 24/7
```

Сервер ничего не знает об агентах: механизмы приносят свои разделы API
(`/api/people`, `/api/memory`, `/api/collections`) и свои панели в
интерфейс. Состояние хода живёт на сервере, идентификатор диалога — в
адресе страницы, поэтому перезагрузка страницы ничего не теряет.

## Где лежат данные

Всё — JSON-файлы в каталоге `-data` (по умолчанию рабочий каталог):

| Каталог | Что там |
|---|---|
| `history/` | диалоги: ветки, точки сохранения, ходы с журналами |
| `memory/long/` | долговременная память, файл на собеседника |
| `memory/work/` | рабочая память, файл на подборку |
| `profiles/` | анкеты собеседников |
| `collections/` | подборки: этап, план, собранные виды, отказы |
| `invariants/` | свод правил справочника |

У демона — одна база SQLite `trivia.db` в его каталоге `-data`: справочник
MDD, выборы видов и кэш проверок, выпуски, сводки и журнал запусков. Схемы
растут миграциями по компонентам (`mdd`, `trivia`, `schedule`).

У каждого файла есть версия формата (`"schema": N`). Файл старого формата
читается через миграцию, а перед первой перезаписью рядом остаётся копия
`<имя>.v<N>.bak`. Файл новее кода не читается — приложение скажет об этом,
а не испортит его.

## Тесты

```bash
go test ./...
```

Тесты не ходят в сеть: модель, Википедия и GBIF подставные.

С детектором гонок:

```bash
go test -race ./...
```

`-race` требует cgo, то есть gcc. На Windows нужен gcc из mingw-w64
(например, из MSYS2: пакет `mingw-w64-x86_64-gcc`), и его каталог должен
стоять **первым** в `PATH`. gcc из `msys64\usr\bin` — cygwin-сборка, cgo её
не принимает («don't use the cygwin compiler…» или просто
«cgo.exe: exit status 2»). В PowerShell:

```powershell
$env:PATH = 'C:\msys64\mingw64\bin;' + $env:PATH
go test -race ./...
```

### Проверки интерфейса в браузере

Интерфейс проверяется в настоящем браузере — headless Microsoft Edge, без
Node и без драйверов:

```bash
go test -tags edge -run TestEdge -v .
```

Тест поднимает приложение на подставной модели с данными во временном
каталоге, заводит диалоги (карточка с разделами и деревом, сравнение в
своей ветке, подборка, пустой диалог) и открывает страницу в Edge с
подключённым сценарием `testdata/edge/scenario.js`. Сценарий нажимает те же
кнопки, что и человек, и пишет итог в страницу; тест снимает DOM
(`--dump-dom`) и превращает каждую строку в подтест — всего около шестидесяти пяти
проверок: пульт, ветки и точки, механизмы и выключатель, лента и карточка,
разделы и «прочитать», дерево и соседи, «почему так», журнал и «Промпты»,
окна, панель подборки с этапами, чипы, выгрузка markdown, новый диалог,
пустое состояние, живой ход, геометрия прокрутки и окно «Интересные факты» на подставном демоне (лента, подробности, поиск, сводки, «Собрать сейчас», экранирование, демон недоступен).

Edge ищется в стандартных местах установки; другой путь — переменная
`EDGE_PATH`. Если браузера нет, тест пропускается.

Снимки экрана тех же состояний:

```bash
EDGE_SHOTS=shots go test -tags edge -run TestEdge .
```

У headless Edge есть особенность: если прокручено само окно, снимок
`--screenshot` рисует страницу со сдвигом — над липким пультом пустое поле
высотой в прокрутку, хотя в DOM пульт стоит у верха. Поэтому для снимков
тест прокручивает `body`, а не окно, а положение пульта и журнала при
прокрутке проверяет по DOM.

## Опыт `-report`: испытания на живой модели

Регрессионный набор испытаний (И-1…И-8) гоняется одной командой вместо
запуска сервера. Каждое испытание сравнивает дорожки, отличающиеся ровно
одним механизмом, и проверяет пороги ТЗ; итог — markdown-отчёт.

```bash
go run . -report                      # все испытания → examples/report.md
go run . -report -trials 1,6          # только И-1 и И-6
go run . -report -report-out out.md   # отчёт в другой файл
```

- Запускать из корня репозитория: проверка совместимости читает
  `testdata/legacy/`.
- Диалоги, профили и подборки прогона остаются в `<-data>/bench/<время>/`,
  по каталогу на испытание: за любым числом отчёта можно пройти в файлы.
- Прогон всех испытаний — сотни запросов к модели; цена прогона есть в
  начале отчёта.
- И-7 (MCP) гоняет три дорожки: A — через MCP-сервер, B — в процессе, B′ —
  повтор B для замера шума модели. На дорожке A сервер убивается посреди
  вызова в шестом запросе: модель должна получить ошибку «MCP-сервер
  недоступен», а следующий ход — пойти через перезапущенный сервер.
  Холодный старт в отчёте включает сборку сервера, если бинарника нет;
  чтобы мерить сам запуск, соберите его заранее
  (`go build -o bin/ ./cmd/animals-mcp`) и передайте путь:
  `go run . -report -trials 7 -mcp-server bin/animals-mcp` (на Windows —
  `bin/animals-mcp.exe`).
- И-8 («Интересные факты по расписанию») собирает не приложение, а демон —
  с настоящими источниками и моделью, но на подставных часах: «час» проходит
  мгновенно. Проверяет выпуски по расписанию, догон после простоя, сводку,
  дневной лимит и инструменты по MCP. Справочник MDD скачивается (15 МБ);
  чтобы не качать его каждый прогон, укажите готовую базу:
  `TRIVIA_MDD_DB=путь/к/trivia.db go run . -report -trials 8`.

## MCP

Инструменты источников (Википедия и GBIF) можно вызывать не в процессе
приложения, а через MCP-сервер — отдельный процесс, который говорит по
протоколу [Model Context Protocol](https://modelcontextprotocol.io) через
stdio. Модель разницы не видит: описания инструментов сверяются с
локальными побайтно, результаты и тексты ошибок те же.

Включить для новых диалогов:

```bash
go run . -features +mcp
```

В открытом диалоге — выключатель «MCP-сервер источников» на пульте. Сервер
запускается при первом ходе с включённым механизмом; где взять бинарник,
приложение ищет так: флаг `-mcp-server путь` → `animals-mcp` рядом с
приложением → `PATH` → сборка из `./cmd/animals-mcp`. Готовые бинарники:

```bash
go build ./...                               # проверка сборки
go build -o . . ./cmd/animals-mcp            # приложение и сервер рядом
```

Что видно в интерфейсе: в журнале хода — `mcp.connect` и `mcp.tools`,
вызовы источников с пометкой «MCP»; окно «MCP-сервер» (кнопка «MCP: …» на
пульте) — статус, инструменты со схемами, счётчики вызовов приложения и
самого сервера. Если сервер не поднялся, ход идёт в процессе, а в журнале
написано почему.

Посмотреть сервер отдельно, без приложения:

```bash
go run ./cmd/mcp-list                        # рукопожатие, инструменты, проверочные вызовы
go run ./cmd/mcp-list -schemas -no-demo      # только список со схемами
go run ./cmd/mcp-list -i                     # ручной режим
```

## Интересные факты: демон 24/7

Демон — тот же бинарник `animals-mcp`, запущенный в долгоживущем режиме.
Он работает сам по себе: приложение, браузер и человек ему не нужны.

```bash
go build -o . ./cmd/animals-mcp
export DEEPSEEK_API_KEY=...        # демон берёт ключ только из окружения
./animals-mcp -http 127.0.0.1:8766 -data ~/animalguide-facts
```

Что он делает:

| Задание | Когда | Что |
|---|---|---|
| `issue` | раз в час (`-every`) | случайный вид из MDD → досье (MDD, Википедия ru/en, наблюдения GBIF за всё время и за 30 дней по странам) → редактор пишет 3–5 фактов со ссылками на источники → проверяющий отдельно сверяет каждый факт с цитируемыми материалами → выпуск в SQLite |
| `summary` | в 09:00 (`-summary-at`) | агрегат за сутки считает код (выпуски, виды, отряды, статусы МСОП, отбраковка, сбои, расход), модель пересказывает его; числа текста сверяются с агрегатом |
| `mdd` | в 04:00 (`-mdd-at`) | проверка нового релиза MDD по ETag; вышел — справочник перезагружается, событие попадает в сводку |

- **Выбор вида.** Статус МСОП выбирается с весом (редкие чаще), вид внутри
  статуса — равновероятно; вид годен, если есть статья в Википедии и не
  меньше 50 наблюдений в GBIF. Повторов нет 30 дней.
- **Лимит.** Не больше `-budget` долларов в сутки (по умолчанию $0.50);
  исчерпан — слот пишется в журнал как `budget`, модель не зовётся.
  Выпуск стоит около $0.002, сводка — около $0.001.
- **Простой.** Демон был выключен — после старта он догоняет ровно один
  пропущенный выпуск, а не все сразу. Первый старт с пустой базой сначала
  скачивает справочник MDD.
- **Разово, без 24/7:** `animals-mcp -run issue` (или `summary`, `mdd`) —
  одно задание и выход; удобно для cron или Планировщика заданий.
- **Без MCP:** `animals-mcp -daemon` — то же расписание без HTTP-сервера.

### MCP по HTTP

С `-http` демон — MCP-сервер (Streamable HTTP, путь `/mcp`, проверка живости
`/healthz`). Инструменты: источники и `mdd_*`, плюс `facts_latest`,
`facts_get` (по id, mdd-id, латинскому, английскому или русскому названию),
`facts_search`, `summary_get`, `schedule_status` и платные `summary_build`,
`run_now` (помечены как меняющие состояние).

Токен — переменная `MCP_TOKEN`: клиенты шлют `Authorization: Bearer …`.
Без токена демон слушает только петлевой адрес; на `0.0.0.0` или внешний
адрес без токена он не запустится.

```bash
go run ./cmd/mcp-list -url http://127.0.0.1:8766                  # список и проверочные вызовы (только чтение)
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call facts_latest -args limit=3
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call facts_get -args '{"species":"Лев"}'
go run ./cmd/mcp-list -url http://127.0.0.1:8766 -call run_now -args job=issue   # платно
```

### Приложение и демон

Приложение ищет демон по `-facts-server` (или `TRIVIA_SERVER`, по умолчанию
`http://127.0.0.1:8766`) с тем же `MCP_TOKEN`. В стартовом выводе — строка
«факты: … (подключён / не отвечает — …)». Окно «Интересные факты» работает
при подключённом демоне. Механизм `trivia` (`-features +trivia` или
выключатель на пульте) даёт ведущему `facts_get` и `facts_latest`: на
вопрос о виде, про который уже есть выпуск, он опирается на выпуск и
называет дату сбора. Демона нет — ход идёт как обычно, в журнале причина.

### Круглосуточно на Windows

Проще всего — отдельное окно консоли: `animals-mcp -http 127.0.0.1:8766`
работает, пока окно открыто; Ctrl+C останавливает его аккуратно (сначала
HTTP, потом планировщик). Чтобы демон поднимался сам после входа в систему, —
Планировщик заданий, а ключ — переменной пользователя:

```powershell
setx DEEPSEEK_API_KEY "..."          # один раз; значение увидят новые процессы
schtasks /Create /SC ONLOGON /TN AnimalGuideFacts /TR "C:\path\animals-mcp.exe -http 127.0.0.1:8766 -data C:\path\facts"
```

Процесс, убитый без сигнала (`taskkill /F`, `Stop-Process`), оставляет
незавершённый запуск в журнале; при следующем старте демон помечает его как
сбойный и продолжает по расписанию.
